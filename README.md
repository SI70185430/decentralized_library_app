# 分散型図書館アプリ

<br />

## サービス概要
社内の複数の場所に保管された書籍を、一つの図書館として利用するための社内向けアプリです。スマートフォン向けのUIで、書籍の検索や保管場所の確認を手軽に行えます。

<br />

## アプリへの想い
様々な場所に点在する書籍について、一つの図書館として気軽に利用できるようにしたいと考えました。<br />
書籍を探したいときに、その場で必要な情報へアクセスできるようにスマートフォン向けに設計しており、<br />
書籍の検索から保管場所・利用状況の確認、貸出・予約・返却までを一元化することを目指しています。

## 今後の課題

本アプリの開発を通じて、機能の追加だけでなく、要件整理・設計判断・実装・検証を一貫して進める必要性を認識しました。

### ポートフォリオ全体に関する課題

#### 設計・実装品質

- 命名、関数の戻り値の記述方法、型注釈、例外・エラーの扱いを統一する。特に、サービス層や API 境界など契約を明確にすべき箇所では、引数・戻り値の型を明示する。
- `globals.css` と共通コンポーネントを活用し、色・余白・ボタンなどの共通スタイルと、画面ごとに重複している UI の実装を整理する。
- 機能やレイヤーごとのディレクトリ構成を見直し、画面表示・入力検証・業務処理・データアクセスの責務を分離する。

#### 開発プロセス・品質保証

- 「1つの作業」の範囲と完了条件を定義し、実装前にスケジュールと依存関係を整理する。
- テストフレームワーク等によるテストの自動化を進め、正常系だけでなく、入力境界値・認可・同時実行・再読み込みを含むテストケースを継続的に検証できるようにする。
- CI/CD を活用し、`lint`・`format`・型チェック・自動テスト・`build` などの品質確認を自動化する。
- 変更の目的が追える粒度で commit し、Conventional Commits などを参考に commit message の形式を統一する。

#### 認証・セキュリティ・堅牢性

- session authentication と CSRF cookie を利用した認証フローについて、cookie 属性、same-origin / cross-origin、ログアウト、セッション期限を理解・文書化し、本番環境の構成に合わせて検証する。
- HTTP API 以外からサービス関数が呼び出される場合も想定し、認可・所有者確認・状態確認をどの層で保証するかを明確にする。呼び出し元を信頼しすぎない guard と、重複しない validation の責務分担を行う。
- エラー応答は利用者向けに安全で分かりやすい文言とし、エラーの種類に応じた処理を設計する。

#### 業務ルール・データ整合性

- テーブルの責務や依存関係を整理し、貸出・返却・予約などの業務処理との整合性を保ちやすいデータモデルに見直す。
- 休館日・臨時休館・返却期限の繰越などを扱うカレンダー／業務日ルールを設計し、実際の運用に対応できるようにする。

#### UI / UX・利用者検証

- スマートフォン向け UI は実機でも確認し、スクロール領域とタップ可能な要素が重なって誤操作を起こさないよう、タップ領域と画面操作を見直す。

#### 本番運用・保守・拡張

- サーバー側では個人情報や認証情報を出力しない logging・監視方針を設計し、障害の検知と原因調査を行いやすくする。
- 利用者向け・運用者向けのドキュメントや手順を充実させ、継続的に引き継げる状態にする。
- 利用範囲の拡大を見据え、データやコンテンツの管理方針、運用体制、今後の拡張方法を検討する。

### 実装内容から得た具体的な課題

#### ログイン・認証

- 社員番号の入力では前後の空白を削除しているが、内部の空白は残る。全角・半角の数字、先頭の `0`、桁数、内部空白をどのように扱うかを要件として定義し、入力・API・DB の型と validation を揃える。
- パスワードは認証値そのものを変えないため、全角・半角変換や一律の trim は行わない。一方で、空白のみの入力が validation を通過するため、認証前に分かりやすい入力エラーを表示する。
- 認証時に社員番号・パスワードを文字列のまま送信しているため、API の入力契約と実際の型を再確認する。

#### 画面遷移・フォーム・ナビゲーション

- 戻る操作は、特定画面へ遷移するよりもブラウザ履歴へ戻る方が自然な場面がある。直リンク時の挙動も考慮し、`router.back()` と遷移先を明示するリンクを画面ごとに使い分ける。
- 入力フォームでは、必須項目・入力例・エラー・disabled 状態を一目で理解できる表現へ統一する。
- 書籍登録画面のサイドメニューには `Dashboard` しかないため、書籍登録・検索などの管理機能間を移動しやすいナビゲーションに改善する。
- ページネーションは、現在ページ・総件数・前後移動の分かりやすさを改善し、検索条件を保った遷移とアクセシビリティを確認する。

#### 検索・貸出・予約機能

- 書籍検索は検索履歴用のテーブルや保存モデルを持たず、毎回 `Book` テーブルを ORM で検索している。検索履歴の保存、検索用 index、cache の必要性を、利用目的・データ量・プライバシーの観点から判断する。
- 貸出完了画面は貸出期間よりも返却期限を中心に表示する方が、利用者にとって分かりやすいかを検討する。また、各完了画面は表示を主な責務としているため、直接アクセスや再読み込み時にも処理結果を確認できるようにする。
- 現在は利用可能な `BookCopy` を対象に予約している。貸出中の書籍への予約待ち、優先順位、通知、失効後の繰り上げを含む予約機能を、実運用の要件から設計する。

#### 利用開始時の導線

- ログイン画面より前に、アプリの目的や利用方法を伝えるトップ画面を用意し、初めて利用する人にも分かりやすい導線を検討する。
